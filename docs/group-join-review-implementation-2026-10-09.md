# 群审核提示实现与实测

## 2026-10-13 权限纠正

下面原始实现记录中“按数量响应确定可展示记录”的判断不足：普通成员也可能读取 total_count。v0.5.36 已撤销此推断。仅原生审核页面的启用“批准”入口可以建立当前账号权限证据；缓存一小时，期限不会因成功读取数量而续期。缺少此证据时不查询、不显示旧数量。自己在原生详情中明确没有管理员标记时撤销已缓存证据；接口拒绝或权限数据不可用时也撤销。

还没有核验列表初始化中的权限字段，因此首次展示要求进入原生审核页面，过期需重新确认。该限制是明确的暂行方案，不能把数量缓存冒充权限。168 项回归测试通过，包含普通成员可读取 13 人但没有权限时仍不发 GET，以及原生批准入口与过期权限的区别。本轮没有对应的在线群详情页可复核，未声称在线权限实测通过。

沿用抓包核验的 api.x.com 原生 GET、查询 ID 和 conversation_id/cursor 参数。页面 MAIN 路径只接受当前原生聊天列表中的群 ID，不开放外部传入 URL；请求前后校验账号和会话，返回结果只含数量，不返回申请人资料。

没有扩展 api.x.com host_permissions。页面跨域请求使用原有当前账号会话，实际读取函数在线返回 count=1。

数量按账号保存在 groupReviews，最多 200 个群；统一后台调度，每次最多 4 个当前可见群，每群至少间隔 60 秒。普通无数据或 403 暂缓 10 分钟，429 使用接口冷却且停止当前批次。聊天列表每 30 秒发现新可见群，后台一分钟闹钟继续补同步。按数量响应确定可展示记录，不猜测未核验的管理员字段。

原生名称旁显示蓝色“待审核 N”。确认 0 后移除。失败或超过两分钟未更新的旧数量标为缓存，悬停显示更新时间和错误。点击或键盘 Enter/Space 跳转原生群详情，再由用户审核。恢复备份后的旧数量标记缓存并重新读取。

164 项测试通过。当前 @RssHunting 的真实聊天群行显示“待审核 1”，与原生详情一致，点击已验证进入对应 info 页面。截图仅保留本地，不推送账号页面图片。
