# 功能路线

## 竞品研究结论（2026-10-04）

成熟产品的共同重点不是“多抓数据”，而是把数据变成下一步动作：

- Fedica 将关注者分群、掉粉追踪、非活跃账号、互动者、关键词监听、统一收件箱和最佳发帖时间放在同一套工作流中。[产品页](https://fedica.com/scheduler-analytics/twitter)
- Typefully 把草稿、计划、队列、日历、建议时段和发布后分析连起来。[日历说明](https://support.typefully.com/en/articles/9210135-scheduling-and-calendar)
- Hypefury 用关键词和指定账号生成待互动队列，回复后从队列移除。[互动说明](https://hypefury.com/features/engagement/)
- Circleboom 强调关注者质量、非活跃账号、掉粉和粉丝历史。[产品页](https://circleboom.com/twitter-management-tool/twitter-circle-tool)
- Redact 的批量清理流程有筛选、预览、逐项排除、备份和任务进度。[清理说明](https://redact.dev/services/twitter/posts)

这些能力可以借鉴交互和数据口径。登录、Cookie、X 内部接口和用户隐私边界不能照搬第三方的服务器模式。

## P0：底层与关系

本次已实现：账号库按用户 ID 去重与按账号隔离；会话检查；端点注册；服务与适配器分层；单页名单同步、失败续传、限流状态；完整快照基线；群成员关系补全；单次关注确认；今日行动入口。

已完成端点内置、账号运行时注入、名单分页和嵌入框架成员引用采集。真实安装后的群成员注入、非空转帖和关注写入仍需要本机实测。

## P1：联系人与每日创作

标签、备注、收藏、暂不推荐。粉丝变化详情与单向关系名单。可设置的每日原创／回复目标，选题与本地草稿。帖子按日期分页，完整统计原创、回复和转帖。增加三项竞品验证过的低风险能力：

1. 关注者分群：按蓝V、互关、简介关键词、粉丝数、最近发帖时间筛选，支持保存筛选视图。
2. 互动队列：把提及、回复、引用和指定关键词命中的帖子合并为待处理队列；完成回复后标记已处理。
3. 发布日历：草稿、计划、已发布内容统一按日历展示，允许拖动改时间；先做本地计划，不自动发布。

当前联系人、互动队列和日历界面尚未交付。创作统计已经支持分页续传，但未结束时仍显示部分覆盖。

## P2：复盘与管理

每周发帖节奏、真实可获取的内容指标、互动联系人、掉粉/新增关注时间线、互动者排行、关键词监听、导出备份与本地数据管理。大规模历史记录存储迁入 IndexedDB。

建议加入“质量提示”而不是直接判定机器人：最近发帖时间、账号年龄、粉丝/关注比、简介是否为空、蓝V和互动记录只能组成可解释的风险提示。不要在没有证据时给用户贴“假粉”标签。

批量取消关注、批量删除和自动发布暂不列入默认功能。若以后加入，必须先做预览、逐项排除、可恢复备份、任务进度和明确的用户触发；Redact 的预览与备份流程值得借鉴，但其破坏性动作不应默认打开。

## 新手流程

确认当前账号与同步时间 → 进群查看简介与关系 → 收藏或逐个关注 → 查看新关注者 → 保存选题与发帖 → 晚间查看创作记录。

关注到固定人数不是首页主目标。蓝V是筛选条件；关系数量和内容反馈分别显示。推荐联系人必须说明推荐依据。首页优先展示“今天该联系谁、为什么、下一步是什么”。

## 建议开发顺序

1. P1-A 联系人标签、备注、收藏和保存筛选视图。
2. P1-B 互动队列，只读采集提及/回复/引用，提供打开原帖和已处理标记。
3. P1-C 本地发布日历和草稿，不接自动发布。
4. P2-A 完整创作历史与掉粉/新增关注时间线。
5. P2-B 互动者排行、最佳发帖时段和关键词提醒。
6. P3 再评估批量动作；任何删除、取消关注或发布动作都采用预览和逐项确认。
