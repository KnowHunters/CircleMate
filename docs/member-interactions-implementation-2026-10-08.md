# 群成员互动记录实现

使用此前原生 HTTP 200 的 NotificationsTimeline GET 与实际 features；queryId 配置存于 notification-endpoint.js，新观察的成功原生请求可更新注册表。未新增推测端点。

按账号存储 memberInteractions。后台每次只读取一页，统一调度串行运行；群列表展示投影中的用户 ID 汇总数据。无需逐个请求群成员。自动扫描在打开 X 页面、读取群缓存及分钟唤醒时推进；扫描结束后间隔五分钟检查新通知。手动同步也遵守限流和十秒防重复间隔。

增量扫描采用持久化 bottom cursor 和已观察通知标识，遇重复页、终点、重复游标或单轮 50 页上限结束本轮。每账号保留至多 5000 条互动关系和 2000 条扫描标识，始终标注部分数据，不能据此宣称完整七日或历史覆盖。

点赞以 actor ID + post ID 去重，且检查帖子作者为当前账号；多用户、多目标的模糊聚合跳过。评论以回复 ID 去重，并检查 in_reply_to_user_id_str。评论内容不额外存储。跨账号切换在网络及保存前沿用会话核验。备份导入校验事件格式，清除导入的分页请求指令。

真实通知响应解析验证：4 条点赞关系、4 条直接评论，成功识别 bottom cursor。156 项自动化测试通过，新增测试覆盖错误结构、错误回复对象、模糊聚合、续页去重、冷却保留缓存。浏览器本地群列表预览验证有记录与暂无记录及同步按钮。

本次尚未重载 Chrome 插件完成真实群列表端到端匹配；真实响应解析与模拟界面验证不能替代这一项。安装更新后需继续核验实际账号和群成员显示。
